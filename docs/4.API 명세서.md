# API 상세 명세서 (v2.0)

> **문서 개요**: 본 문서는 시스템 간 통신 규격을 정의하며, 크게 **Client(App) ↔ Backend(Java)** 와 **Backend(Java) ↔ AI Server(Python)** 두 가지 파트로 나뉩니다.
> **RabbitMQ**는 내부 인프라 통신용이므로 본 REST API 명세에는 포함되지 않습니다.

---

# Part 1. Frontend ↔ Backend API
> **Mobile App**과 **Java Backend** 간의 통신 규격입니다.
> - **Base URL**: `https://api.car-sentry.com/api/v1`
> - **Global Prefix**: 모든 API 엔드포인트 앞에는 자동으로 `/api/v1`이 붙습니다. (아래 경로는 이 접두어 이후의 상대 경로입니다.)
> - **Auth**: `Authorization: Bearer {jwt_token}`

### 📦 공통 응답 규격 (Common Response)
모든 API 응답은 `ApiResponse` 객체로 래핑되어 전달됩니다.
```json
{
  "success": true,
  "data": { ... },
  "error": null
}
```
- **success**: 요청 처리 성공 여부 (boolean)
- **data**: 실제 결과 데이터 (성공 시에만 존재, 실패 시 null)
- **error**: 에러 정보 (실패 시에만 존재, 성공 시 null)
  - `code`: 에러 코드
  - `message`: 상세 에러 메시지

## 1. 사용자 및 인증 (Auth & Users)
> Base Path: `/auth`

### 1.1 회원가입 (Signup)
- **POST `/auth/signup` (BE-AU-001)**
- **Request Body**:
  ```json
  {
    "email": "user@example.com",
    "password": "password123",
    "nickname": "carlover"
  }
  ```
- **Response**: `ApiResponse<UserResponse>`
  ```json
  {
    "success": true,
    "data": {
      "userId": "UUID",
      "email": "user@example.com",
      "nickname": "carlover",
      "profileImageBase64": "string (null if empty)"
    },
    "error": null
  }
  ```

### 1.2 로그인 및 토큰 (Login & Token)
- **POST `/auth/login` (BE-AU-002)**: JWT 토큰 발급
- **Request Body**:
  ```json
  {
    "email": "user@example.com",
    "password": "password123"
  }
  ```
- **Response**: `ApiResponse<TokenResponse>`
  ```json
  {
    "success": true,
    "data": {
      "accessToken": "ey...",
      "refreshToken": "ey..."
    },
    "error": null
  }
  ```

- **POST `/auth/refresh`**: 토큰 갱신
- **Request Body**: `{ "refreshToken": "string" }`
- **Response**: `ApiResponse<TokenResponse>`

### 1.3 사용자 프로필 (User Profile)
- **GET `/auth/me` (BE-AU-003)**: 내 프로필 조회
- **Response**: `ApiResponse<UserResponse>`

- **PATCH `/auth/me` (BE-AU-004)**: 프로필 수정
- **Request Body**: `{ "nickname": "string", "memo": "string" }`

- **POST `/auth/me/image`**: 프로필 이미지 업로드
- **Request**: `Multipart/form-data` 파라미터 `file` (이미지 파일)

- **PATCH `/auth/fcm-token`**: FCM 토큰 전용 갱신
- **Request Body**: `{ "fcmToken": "string" }`

- **DELETE `/auth/me` (BE-AU-007)**: 회원 탈퇴 (Soft Delete)

## 2. 차량 관리 (Vehicles)
> Base Path: `/vehicles`

### 2.1 차량 등록
- **POST `/vehicles` (BE-VH-001)**: 차량 수동 등록
- **Request Body**:
  ```json
  {
    "manufacturer": "Hyundai",
    "modelName": "Avante",
    "modelYear": 2022,
    "fuelType": "GASOLINE",
    "totalMileage": 15000.5,
    "carNumber": "123가4567",
    "nickname": "My Car (Optional)",
    "memo": "Daily drive (Optional)",
    "obdDeviceId": "OBD-XYZ-001 (Optional)",
    "consumables": [
      {
        "code": "ENGINE_OIL",
        "lastReplacedAt": "2024-01-01T00:00:00",
        "lastReplacedMileage": 10000.0
      }
    ]
  }
  ```
- **Note**: `consumables` 리스트는 선택 사항입니다. 입력하지 않은 소모품(9종 전체 대상)은 시스템 표준 주기에 따라 자동으로 상태가 추론되어 초기화됩니다.
- **Response**: `ApiResponse<VehicleDto.Response>`
  ```json
  {
    "success": true,
    "data": {
      "vehicleId": "UUID",
      "userId": "UUID",
      "manufacturer": "Hyundai",
      "modelName": "Avante",
      "modelYear": 2022,
      "fuelType": "GASOLINE",
      "totalMileage": 15000.5,
      "carNumber": "123가4567",
      "nickname": "My Car",
      "memo": "Daily drive",
      "isPrimary": false,
      "registrationSource": "MANUAL",
      "obdDeviceId": "OBD-XYZ-001"
    },
    "error": null
  }
  ```

- **POST `/vehicles/obd` (BE-VH-002)**: OBD 기반 차량 자동 등록 (VIN 자동 매핑)
- **Request Body**: `{ "vin": "17_CHAR_VIN_CODE" }`
- **Response**: `ApiResponse<VehicleDto.Response>`

### 2.2 차량 조회 및 수정
- **GET `/vehicles` (BE-VH-004)**: 보유 차량 목록 조회
- **Response**: `ApiResponse<List<VehicleDto.Response>>`

- **GET `/vehicles/{id}` (BE-VH-004)**: 차량 상세 정보 조회
- **Response**: `ApiResponse<VehicleDto.Response>`

- **PUT `/vehicles/{id}` (BE-VH-004)**: 차량 정보 수정 (별명, 메모)
- **Request Body**: `{ "nickname": "string", "memo": "string" }`

- **PATCH `/vehicles/primary` (BE-VH-006)**: 대표 차량 설정
- **Request Body**: `{ "vehicleId": "UUID" }`

- **DELETE `/vehicles/{id}` (BE-VH-007)**: 차량 삭제 (Soft Delete)

### 2.3 마스터 데이터 (Master Data)
> Base Path: `/master`

- **GET `/master/manufacturers` (BE-VH-003)**: 제조사 목록 조회 (예: Hyundai, Kia)
- **Response**: `ApiResponse<List<String>>`

- **GET `/master/models` (BE-VH-003)**: 모델 목록 조회 (파라미터: manufacturer)
- **Response**: `ApiResponse<List<CarModelDto>>`

## 6. AI 진단 및 리포트 (AI Diagnosis)
> Base Path: `/ai`

### 6.1 통합 진단 요청
- **POST `/ai/diagnose/unified`**: 멀티모달 통합 진단 요청 (Multipart)
- **Request (Multipart)**:
  - `data`: `UnifiedDiagnosisRequestDto` (JSON String)
  - `audio`: 오디오 파일 (Optional)
  - `image`: 이미지 파일 (Optional)
- **Response**: `ApiResponse<DiagnosisResponseDto>`

### 6.1.1 대화형 진단 답변 (Reply) [NEW]
- **POST `/ai/diagnose/session/{sessionId}/reply`**
- **Description**: AI의 추가 정보 요청(INTERACTIVE 모드)에 대한 사용자의 답변(텍스트/사진/음성)을 전송합니다. 비동기로 처리됩니다.
- **Request (Multipart)**:
  - `data`: `ReplyRequestDto` (JSON String: `{ "userResponse": "냉각수 냄새가 나요" }`)
  - `image`: 추가 이미지 파일 (Optional)
  - `audio`: 추가 녹음 파일 (Optional)
- **Response**: `ApiResponse<Map<String, Object>>`
  ```json
  {
    "success": true,
    "data": {
      "message": "답변이 접수되었습니다. 분석 완료 후 결과가 업데이트됩니다.",
      "sessionId": "UUID",
      "status": "REPLY_ACCEPTED"

    "error": null
  }
  ```

- **GET `/ai/diagnose/session/{sessionId}` (BE-AI-006)**: 진단 결과 상세 조회

- 3.2 Common Response Envelope (Core & Extensions)
  - 모든 Core 및 Extension 결과는 본 Envelope를 기본 구조로 사용합니다.
  - 각 도메인은 Envelope 외에 추가 필드를 가질 수 있으나, 도메인 전용 정보는 `details`에 포함하는 것을 권장합니다.
  - `options.extensions`가 비어 있거나 미지정인 경우에도 응답은 `"extensions": {}`를 반환합니다.

  ```json
  {
    "domain": "string",
    "status": "PROCESSED | SKIPPED | UNSUPPORTED | ERROR",
    "method": "ml | rule | hybrid",
    "score": "number | null",
    "threshold": "number | null",
    "is_anomaly": "boolean",
    "details": "object"
  }
  ```

  - Rule 기반(`method=rule`)의 `score`/`threshold`:
    - `score`: 0/1 (해당 도메인에서 이상 룰이 1개 이상 triggered면 1, 아니면 0)
    - `threshold`: 기준값이 존재하면 number, 기준이 없는 룰/체크면 null
    - Rule 기반 결과의 `details.rules` 항목은 최소한 다음 필드를 포함합니다.
      - `id`: 룰 식별자
      - `feature`: 검사 대상 신호
      - `value`: 평가된 실제 값
      - `triggered`: 룰 발동 여부 (boolean)
