3.1.1 Score Aggregation Policy (anomaly_score 정의)

입력 데이터는 options.window_sec / options.stride_sec 기준으로 다중 윈도우로 분할됩니다.

각 윈도우마다 window_score가 계산됩니다.

anomaly_score는 기본적으로 모든 윈도우의 최댓값(max window_score) 으로 정의합니다.

예: anomaly_score = max(window_scores)

최종 is_anomaly는 아래 정책을 따릅니다:

is_anomaly = (anomaly_score >= policy.threshold)

최상위 anomaly_score/is_anomaly는 전체 Fusion 결과(Engine + Rules) 기준입니다.

3.1.2 Engine Hybrid Model & Fallback Policy (불규칙 컬럼 대응)

엔진 도메인은 다음의 하이브리드 구조로 이상 점수를 산출합니다.

Stat One-Class: 정상 분포 기반 통계/요약 피처로 이상 점수 산출 (안정장치, 가능한 한 수행)

LSTM-AE: 정상 재구성 기반 이상 점수 산출 (Core10 입력이 충분할 때만 수행)

Ensemble: final_score = w1 * score_stat + w2 * score_ae (기본 w1=w2=0.5)

(A) Schema Align

입력의 features는 가변 Dict입니다.

엔진 ML은 schema_version(core10-v1) 순서로 벡터를 구성합니다.

누락 feature는 NaN으로 채우고 mask=0으로 표시합니다.

(B) LSTM-AE 실행 조건 (SKIPPED 조건)

아래 중 하나라도 만족하지 않으면 LSTM-AE는 SKIPPED 처리합니다.

Core10 중 유효 feature 수가 최소 기준 미만 (예: < min_features)

윈도우 내 coverage가 최소 기준 미만 (예: < min_coverage, 기본 0.9)

샘플 수 부족 등 전처리 조건 미충족

(C) Fallback

LSTM-AE가 SKIPPED되면, 엔진 점수는 Stat One-Class 결과로 fallback 합니다.

engine_score = score_stat

엔진 자체가 계산 불가(coverage 극저하 등)일 경우:

engine.status = SKIPPED, engine.score = null

NOTE: 위 정책을 통해 차종별 PID 누락이 있어도 API는 정상 응답을 반환하며,
엔진 도메인은 가능한 범위에서 최선의 추론을 제공합니다.

3.1.3 Policy (Threshold / K consecutive / Cooldown)

domains.<domain>.threshold는 도메인별 기준값이며, 엔진의 경우 기본적으로 policy.global_threshold와 동일하게 운영할 수 있습니다.

threshold는 val set에서 산출된 값을 사용합니다(운영 시 서버 정책 파일로 관리).

운영 안정성을 위해 다음 정책을 적용할 수 있습니다(서버 정책):

K consecutive: score >= threshold가 연속 K회 이상일 때만 알람/이벤트 확정

cooldown: 알람 발생 후 일정 시간 내 중복 알람 억제

Severity는 기본적으로 score 및 지속시간(연속 초과 길이)을 기반으로 정의할 수 있습니다.

- 3.2 Domain Result Schema

```json
{
  "domain": "string",
  "status": "PROCESSED | SKIPPED | UNSUPPORTED | ERROR",
  "score": "number | null",
  "threshold": "number | null",
  "is_anomaly": "boolean",
  "top_signals": [
    {
      "feature": "string",
      "contribution": "number(0~1)"
    }
  ]
}
```

domain (string): 예) engine

status (string): PROCESSED | SKIPPED | UNSUPPORTED | ERROR

PROCESSED: 정상 분석 완료

SKIPPED: 조건 불충족으로 미수행 (예: mode=DRIVING에서 idle, 또는 엔진 ML 조건 미충족)

UNSUPPORTED: 차량/데이터 상 지원하지 않는 도메인

ERROR: 분석 중 오류 발생

score (float|null): 이상 점수(0~1). 값이 클수록 정상 패턴과의 차이가 큼

threshold (float|null): 이상 판단 기준값

is_anomaly (bool): score >= threshold인 경우 true

top_signals (array<object>, optional):

이상판단에 크게 기여한 센서(feature) Top-k

feature (string): 센서(feature) 이름

contribution (float): 상대 기여 비중(0~1)

최대 top_k개 반환 (항상 고정 개수 아님)

주로 ML 도메인(예: engine)에서 제공, Rule 도메인은 생략 가능 또는 빈 배열 가능

- 3.3 Event Schema

```json
{
  "type": "string",
  "domain": "string",
  "feature": "string",
  "value": "number | string | null",
  "threshold": "number | null",
  "window_index": "number | null",
  "severity": "INFO | WARNING | CRITICAL",
  "message": "string"
}
```

이상 이벤트는 feature 필드 포함 필수

백엔드 전달/알림/로그/후속 리포트 생성은 events[]를 표준으로 사용

- 3.4 Raw Response Policy

options.return = "summary": window_results는 빈 배열 또는 생략

options.return = "raw": window_results 포함 (디버깅/분석용)

- 3.5 Compatibility & Deprecation

Deprecated (응답): core, extensions, details.rules 중심 중첩 구조

Deprecated (입력): options.extensions

권장 표준 (응답): is_anomaly + anomaly_score + domains + events[]
