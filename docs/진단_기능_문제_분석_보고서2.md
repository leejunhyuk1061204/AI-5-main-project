## [백엔드] 로직 유실 및 구조 파괴 (핵심 문제)

단순한 주석 처리를 넘어, 기존의 정상 작동하던 로직이 삭제되거나 다른 코드로 **대체**되었습니다.

### 1. AiDiagnosisService.java: 주요 로직 증발
- **AI 호출 코드 삭제**: `aiClient.callComprehensiveDiagnosis`를 호출하여 실제 분석 결과를 받던 약 10줄의 로직이 사라지고, 하드코딩된 `HashMap` 더미 데이터로 대체됨. (406번 줄 부근)
- **결과 저장 로직 변질**: 이전 버전의 `Builder` 패턴 기반 저장 로직이 사라지고, DB에서 객체를 찾아와 `set` 하는 방식으로 전면 수정됨.
- **도메인 필드 불일치**: `getManufacturer()` 대신 `getManufacturerEn()` 등을 사용하게 코드가 바뀌어, 단순히 예전 코드를 붙여넣으면 컴파일 에러가 발생함.

### 2. AiClient.java: API 인터페이스 파괴
- **Multipart 전송 로직 삭제**: 로컬 서버의 파일을 AI 서버로 보내던 `callMultipartApi` 메서드와 관련 로직이 삭제됨.
- **S3 URL 방식으로 강제 전환**: 현재는 S3 URL을 전송하는 방식으로만 코드가 짜여 있어, 기존의 로컬 파일 기반 진단 시스템과 호환이 끊김.

---

### 3. 알림 발송 임의 차단 (AiDiagnosisService.java:632-636)
- **증상**: 진단 결과가 나와도 사용자에게 알림(FCM)이 오지 않음.
- **원인**: `if (trigger == DiagTriggerType.DATA || ...)` 구문을 넣어 사용자가 직접 요청한 진단은 알림을 스킵하도록 입구를 막아버림.
- **영향**: 사용자님이 구축한 RabbitMQ 기반의 비동기 알림 시스템이 실행조차 되지 못함.

## 전용 복구 계획 (Surgical Restoration)


단순 `git checkout`으로는 해결이 안 되며, 강현님이 바꾼 '기반 공사(S3, 영칭 사용)'는 유지하면서 **'끊긴 혈관(AI 호출 및 폴링)'**만 다시 잇는 수술이 필요합니다.

### 1. 백엔드 복구 
- `AiDiagnosisService.java`에서 하드코딩된 더미 생성 로직을 제거하고, 현재의 S3 구조에 맞게 `aiClient` 호출 로직을 재구성합니다.
- 영문 명칭(`En`) 필드를 사용하도록 바뀐 도메인에 맞춰 AI 요청 객체 생성기를 보정합니다.

### 2. 프론트엔드 로직 재이식
- `ObdDiagLoading.tsx`에 구버전의 폴링 로직을 다시 심어, 화면은 신규 디자인을 쓰되 데이터는 실제 서버 상태를 추적하게 만듭니다.

### 3. AI 서버 연동 정렬
- `AiClient.java`의 URL 엔드포인트를 AI 서버 명세(`/v1/visual`, `/v1/predict/audio` 등)와 포트(`8000`)에 완벽히 일치시킵니다.
